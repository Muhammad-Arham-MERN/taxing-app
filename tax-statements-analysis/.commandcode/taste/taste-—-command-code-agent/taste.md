# Taste — Command Code agent
- Expects the agent to consult the central `PROJECT_MAP.md` for project understanding before implementing changes in this codebase (explicitly instructs "use the main PROJECT_MAP.md for better project understanding"). Confidence: 0.6
- Expects database migrations to be idempotent and self-guarding: scripts should detect already-applied state and no-op instead of re-running unconditionally on every release/CI run. Confidence: 0.6
- Feeds the agent raw runtime/application debug logs (timestamped, level-tagged lines) as diagnostic evidence when reporting a bug, rather than describing it in the abstract — expects the agent to reason from those logs to the actual root cause. Confidence: 0.5
- Expects migrations to be additive and data-preserving — asks explicitly whether existing local/cloud data survives, whether the schema upgrade touches only the intended tables, and whether records being dropped are copied before being replaced. Confidence: 0.7
- Prefers keeping release automation minimal: for small-scale projects, avoids running cloud DB migrations as a CI/GitHub Actions job and instead runs an explicit manual script alongside the release — reasons that CI-held cloud secrets and automatic cloud migrations are more moving parts than the user base warrants; later explicitly instructs the agent to strip the migration job from the workflow, keeping only build/sign/publish. Confidence: 0.8
- Prefers credentials/config to live in a local git-ignored `.env` (with an `.env.example`) loaded by the script, rather than manually exporting every environment variable or wiring them into CI secrets. Confidence: 0.6
- Expects the agent to change only what was explicitly requested: treats musings and stated future intentions as discussion, not as work orders, and reacts sharply ("i did not tell you to do this, revert all changes back") when the agent unilaterally implements them — then expects a precise revert of just the offending edits. Confidence: 0.7
